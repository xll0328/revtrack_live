## Issue-Ledger Calibrator

- script: [run_issue_ledger_calibrator.py](/data/sony/emnlp2026_revtrack/scripts/run_issue_ledger_calibrator.py)
- logic: [issue_ledger.py](/data/sony/emnlp2026_revtrack/src/revtrack/issue_ledger.py)
- metrics: [iclr2024_clean_dev_assistant_issue_ledger_metrics.json](/data/sony/emnlp2026_revtrack/outputs/day1/iclr2024_clean_dev_assistant_issue_ledger_metrics.json)

The calibrator uses `mpnet_label` as the base guess, then overrides it only when the issue ledger contains strong evidence:

- explicit reviewer follow-up comments
- strong negative follow-up cues for `regressed`
- clear broad-scope requests that received only partial new evidence
- `regressed -> partially_fixed` softening when the response clearly adds new experiments or runtime evidence

Result:

- accuracy: `0.900`
- macro F1: `0.910`

Main finding:

- a lightweight structured ledger can beat raw semantic matching by a large margin on this dev set
- the biggest gain comes from respecting explicit reviewer follow-up signals and separating `partial repair` from `full closure`
- `regressed` appears recoverable with explicit negative evidence, but raw text encoders almost never catch it on their own

Main finding:

- the new `fixed <-> partially_fixed` tranche does exactly what we wanted: it makes the benchmark materially harder for all semantic baselines
- after correcting for feature leakage, `Structured` is still the best model on both accuracy and macro-F1, but now by a believable rather than suspicious margin
- the strongest paper claim is no longer “structured is nearly solved”; it is “structured evidence slots plus selective follow-up overrides still beat pure semantic matching on a deliberately hardened revision benchmark”
- `Issue-Ledger` remains valuable because it protects minority labels and especially `regressed`, but it is now clearly too conservative on `unresolved`
- the no-override ablation still matters: once the hard follow-up overrides are removed, `Structured` falls back toward the encoder baselines
